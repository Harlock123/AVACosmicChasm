# AGENTS.md

Notes for anyone, human or AI agent, changing this code. `README.md` covers playing the game, its controls and
what the tests check; this file covers how the code is put together and the rules that keep it working.

## What this is

A colour vector shooter in the style of Cinematronics' 1983 arcade game Cosmic Chasm, in C# on .NET 10 and
Avalonia 12, drawn through Avalonia's `DrawingContext`. One self-contained executable per platform (Windows, macOS and Linux, x64 and
ARM). Everything in it is original: the graphics are drawn in code, and the sounds and music are synthesised by
`tools/make_sounds.py` (the title tune is an arrangement of Bach's public-domain Toccata in D minor).

## Commands

```bash
dotnet build AVACosmicChasm.slnx                  # the SDK version is in global.json (10.0.400 or later)
dotnet test AVACosmicChasm.slnx                   # every test runs headless: no window opens
dotnet run --project src/AVACosmicChasm           # play it; --no-audio for silence
CHASM_SHOTS=$PWD/Images dotnet test tests/AVACosmicChasm.Tests --filter ScreenshotTests   # refresh the README's pictures
CHASM_PROBE=1 dotnet test tests/AVACosmicChasm.Tests --filter PilotProbe   # how the computer pilot fares, for tuning
python3 tools/make_sounds.py                      # rebuild src/AVACosmicChasm/Sounds (standard-library Python only)
```

`PilotProbe` does nothing unless `CHASM_PROBE` is set; a number above 1 starts it at that station, and
`CHASM_SEEDS` (default `1,2,3`) picks the seeds. `Directory.Build.props` sets `TreatWarningsAsErrors`, nullable
reference types and implicit usings for every project: a warning fails the build, so keep it at zero.

## Layout

- `src/AVACosmicChasm/Engine/`: the game, with no Avalonia drawing in it.
  - `GameEngine.cs` runs the states (title, attract, play, pause, game over, initials, high scores) and the
    fixed-step loop.
  - `Sim.cs` steps the world: the ship, the closing walls, the drill, enemies, the core and the escape.
  - `World.cs` has the screen's measures (`Field`) and the things in a room.
  - `Station.cs` builds a station: the grid of rooms, the doorways between them, and the seeded `Dice`.
  - `Pilot.cs` is the computer player, used by the attract mode and the tests.
  - `InputHandler.cs` (keys) and `ControllerManager.cs` (SDL2 gamepads) produce `Controls`.
  - `HighScoreTable.cs`, `InitialsEntry.cs` and `SoundManager.cs` do what their names say.
- `src/AVACosmicChasm/Views/`: `GameCanvas` (split over two partial files) draws the 1024x768 frame as glowing
  vector lines and runs the 60 Hz timer.
- `src/AVACosmicChasm/Audio/`: the OpenAL Soft audio engine, shared with the author's other AVA games.
- `src/AVACosmicChasm/Sounds/`: the WAV files the game plays, generated by `tools/make_sounds.py`.
- `tests/AVACosmicChasm.Tests/`: xUnit v3 with `Avalonia.Headless.XUnit`. `Harness.cs` sets up games, quiet
  worlds and parked ships.

## Rules that keep it working

- **Fixed steps.** The simulation advances in fixed 1/60 s steps (`Sim.Step`, `Field.Step`), independent of the
  frame rate, so tests can play whole stations deterministically from a seed. Draw random numbers from the world's
  seeded `Dice` (`w.Dice`), never from `Random.Shared`.
- **Engine first, drawing second.** Gameplay belongs in `Engine/`, where tests can reach it without a window.
  `Views/` only reads the world and draws it.
- **Input goes through `InputHandler`.** There is no `dy`: `Controls` is turn, thrust, fire and shield. Up (key,
  D-pad, or a negative stick Y) thrusts and down raises the shield. Test new controls through `InputHandler`
  (`InputTests`), not by setting `Controls` directly.
  - Keys are tracked by `PhysicalKey`, because on some Linux setups Avalonia reports the release of Shift as
    CapsLock. `ShiftReleaseTests` covers this.
- **SDL under one lock.** `ControllerManager` starts, polls and stops SDL only inside `lock (Sdl)`. The tests
  create many handlers in parallel, and unlocked SDL calls corrupt its heap.
- **Audio.** OpenAL Soft through Silk.NET. `Directory.Build.targets` swaps in the official Windows `soft_oal.dll`
  from `Audio/native/`, which needs no Visual C++ runtime. In a virtual machine `OpenAlConfig` writes a larger
  mixing period to `ALSOFT_CONF` so the sound doesn't break up.
- **Tests never touch the player's files.** High scores live in the app-data folder (`AVACosmicChasm`); tests
  load the table from a temporary folder (`Harness.TempFolder()`) and run silent.

## Making a change

- Add or update tests with every gameplay change. `dotnet test` must pass, with no warnings.
- If the change shows on screen, refresh the screenshots with the command above, and look at them.
- Update `README.md` (features, controls, the test list) to match.
- New sounds go into `tools/make_sounds.py`, not as hand-edited WAV files.

## CI and releases

`.github/workflows/build.yml` builds and tests every push. It then publishes self-contained single-file builds for
win-x64/x86/arm64, linux-x64/arm64/arm and osx-x64/arm64. Every run keeps the builds as workflow artifacts.
Only pushes to `main` replace the assets of the `latest` pre-release, and a `v*` tag makes a proper release.
A release run then asks the portfolio site to rebuild, if the `SITE_REFRESH_TOKEN` secret is set.
